# Pharos Driver — кликабельный прототип

HTML + Tailwind (React + Vite) прототип приложения водителя, собранный **1:1 с дизайном в Figma**.
Цель: сначала живой прототип, потом перенос решений обратно в Figma.

## Быстрый старт

```bash
pnpm install
pnpm dev          # прототип на http://localhost:5173
pnpm storybook    # витрина компонентов на http://localhost:6006
```

## Как посмотреть (для людей и для агентов)

**На этой же машине** — репозиторий уже склонирован, а витрина обычно поднята:

```bash
pnpm install
pnpm dev          # прототип на http://localhost:5173
pnpm storybook    # витрина компонентов на http://localhost:6006
```

Дев-сервер Storybook живёт по адресу, с которым его запустили (в этой сессии — `http://localhost:6007`).
Проверять, что он поднят, удобно через `curl -s http://localhost:6007/index.json | head -c 200`.

**С другого компьютера или из другого агента** — ничего из `localhost` не видно, нужно:

1. **Доступ к репозиторию.** Он **приватный**, анонимный `git clone` не сработает. Варианты:
   добавить аккаунт агента/коллеги в Settings → Collaborators, выдать ему fine-grained PAT на чтение,
   либо сделать репозиторий публичным.
2. **Опубликованный Storybook.** Сборка статическая и использует **относительные пути**, поэтому
   кладётся в любой подкаталог без пересборки:

   ```bash
   pnpm build-storybook          # → storybook-static/ (~10 МБ, 245 сторей)
   ```

   Дальше любой из вариантов:
   - **GitHub Pages** — workflow уже лежит в `.github/workflows/storybook.yml`; нужно один раз
     включить Settings → Pages → Source: **GitHub Actions**. Адрес будет
     `https://designantonyui-source.github.io/pharos-driver-prototype/`.
     ⚠️ Pages для **приватного** репозитория требует платного плана GitHub (Pro/Team/Enterprise).
   - **Cloudflare Pages / Netlify / Vercel** — подключаются к приватному репозиторию на бесплатном
     плане: команда сборки `pnpm install --frozen-lockfile && pnpm build-storybook`, каталог
     `storybook-static`.
   - **Отдельный публичный репозиторий** только под артефакт: выложить туда содержимое
     `storybook-static` и включить Pages у него.

**Что агент должен прочитать перед работой:** `AGENTS.md` (правила) и `design/PORT-LOG.md` —
это не отчёт, а брифинг: метод сверки с Figma (§1), 30 ловушек самого Figma-файла (§2) и замеры
по каждому уже перенесённому компоненту. Журнал экономит часы: он ловит и врущие имена слоёв,
и расхождение рендера с API, и растянутые высоты вариантов.

## Как пройти путь водителя

1. Открой `/` — это карта экранов.
2. Happy path: `Loads → карточка груза → details v2 → Send application → Loads с баннером → Application status → Trip`.
3. Ожидания (одобрение диспетчера, подтверждение клиента) в реальном времени не случаются —
   используй **Demo-панель** в правом нижнем углу: «→ sent», «→ dispatcher approved», «→ customer confirmed», «→ reset».
4. Состояние живёт в `localStorage`: перезагрузка страницы путь не сбрасывает.

## Где что лежит

| Путь | Что это |
|---|---|
| `src/components/` | компоненты (единственный источник правды), у каждого — стори-файл |
| `src/components/Icon.tsx` | единый реестр иконок: маппинг имён Figma ↔ lucide в одном месте |
| `src/screens/` | экраны, один файл = один экран Figma |
| `src/assets/` | SVG-экспорты из Figma (флаги, арт карт) |
| `src/lib/api.ts` | мок-API: переключение на реальный бэкенд = правка только этого файла |
| `src/lib/store.ts` | состояние заявки, persist в localStorage |
| `design/tokens.json` | токены (экспорт из Figma) → `src/styles/tokens.css` через `pnpm tokens` |
| `design/figma-map.md` | таблица «node-id в Figma ↔ файл/компонент в коде» |
| `design/PORT-LOG.md` | журнал переноса: метод сверки, ловушки Figma-файла, замеры по каждому компоненту |
| `tools/audit-tokens.mjs` | гвард: каждый `var()` обязан существовать; входит в `pnpm check` |

## Правила (важно для агентов)

Читай `AGENTS.md`. Коротко: не хардкодить значения, брать их из токенов; у компонента и экрана —
шапка-контракт с node-id из Figma; новый экран = новый роут + запись в `figma-map.md`;
компонент считается перенесённым только после замера и записи в `design/PORT-LOG.md`.
