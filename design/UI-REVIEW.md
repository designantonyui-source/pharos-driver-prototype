### P0-2. `Button.tsx` не имеет focus-ring — вообще

Замер `grep -c focus-visible`:

```
TripDetails.tsx:1  ApplicationTracker.tsx:1  SmartLoadList.tsx:1
Button.tsx:0  LoadCard.tsx:0  LoadCta.tsx:0  ApplicationBanner.tsx:0
Home.tsx:0  V2Frame.tsx:0  QuickApplyModal.tsx:0  Sheet.tsx:0  DemoToggle.tsx:0
```

**Три файла из четырнадцати.** При этом `Button.tsx` — самый используемый компонент прототипа.
Живой замер тап-таргетов на `/v2` подтверждает: `focusRing:n` у фильтров, карточек, CTA и таб-бара;

(«visible keyboard focus») и WCAG 2.4.7. Токен уже есть: `--color-focus-ring: #225d74`.

Правка в одном месте — `Button.tsx`, наследуется всеми вызовами:

```
focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-[var(--color-focus-ring)]
```

### P0-3. Контраст ниже WCAG AA

Расчёт по relative luminance (норма 4.5:1 для обычного текста, 3.0:1 для крупного):

| Пара | Контраст | Вердикт |
|---|---|---|
| `text-tertiary #80929e` на `bg-canvas #f4f6f8` | **2.97:1** | FAIL |
| `load-pending-accent #f59e0b` на `load-pending-bg #fffbeb` | **2.07:1** | FAIL |
| `load-booked-accent #16a34a` на `load-booked-bg #f0fdf4` | 3.15:1 | large-only |

## P1 — рассогласование дизайн-системы

### P1-1. Две конкурирующие палитры состояний на одной карточке

`design/tokens.json` содержит **два параллельных набора** семантических цветов:

| Роль | Палитра Фигмы (`color-status-*`) | `color-load-state-*` |
|---|---|---|
| success | `#e8f6ef` / `#216547` (6.25:1) | `#f0fdf4` / `#16a34a` (3.15:1) |
| warning | `#fff4df` / `#855300` (5.95:1) | `#fffbeb` / `#f59e0b` (2.07:1) |
| danger | `#fdedea` / `#b8332f` (5.20:1) | `#fef2f2` / `#ef4444` |
| neutral | `#eff2f5` / `#526773` (5.27:1) | `#f9fafb` / `#9ca3af` |

`#f59e0b`, `#16a34a`, `#ef4444`, `#9ca3af` — это **дефолтная палитра Tailwind** (amber-500, green-600,
red-500, gray-400), а не семейство Pharos. Остальные токены файла — связный teal/slate
(`#225d74`, `#172a35`, `#586d79`, `#bce5d5`). Группа `color-load-state` выглядит как чужая система,
приставленная сбоку. Это классический признак сгенерированной страницы, а не решения для этого брифа.

Хуже того: `LoadCard.tsx:16-19` использует **обе палитры на одной поверхности** —
левая граница из `color-load-state-*-accent`, бейдж из `color-status-*`:

```ts
pending: { container: '... border-l-[var(--color-load-state-pending-accent)]',
           badge: 'bg-[var(--color-status-warning-bg)] text-[var(--color-status-warning-text)]' }
```

Один и тот же смысл «в ожидании» закодирован двумя разными оттенками жёлтого в одной карточке.

**Правка:** убрать группу `color-load-state-*`, выразить состояния через `color-status-*` +
прозрачность акцента. Контраст P0-3 чинится автоматически, дублирование смысла исчезает.
Акцент границы — `color-mix(in srgb, var(--color-status-warning-text) 55%, transparent)`,
что держит границу читаемой, не вводя новый токен.

### P1-2. Ставка понижена относительно замеренного с Фигмы эталона

### P1-4. Двойной знак валюты — **ОТОЗВАНО, не реализовано**

`LoadCard.tsx:78` → `€360 €2.85/km` · `QuickApplyModal.tsx` → `€360 · €2.85/км`.

Исходная претензия: две суммы с `€` подряд читаются неоднозначно.

**Пункт снят как ошибочный.** Проверка перед реализацией показала, что `€X.XX/km` со знаком евро —
не дефект, а **последовательная конвенция всего репозитория**: `OfferCard.tsx:73,135`,
`OfferTerms.tsx` (+`stories:17,29`), `OfferPreview.tsx:66`, `v2/LoadSheet.tsx:39`, v1 `LoadCard.tsx:285`,
`ScreenFrame.stories.tsx:20` и `bl/List.tsx:84,272` — все 8+ мест пишут удельную цену с `€`.
Правка затронула бы одно место из девяти и **создала** бы рассогласование вместо того, чтобы снять его.

По смыслу знак тоже нужен: `2.85/km` без валюты неоднозначно (2.85 чего — евро, километров,
минут?), тогда как `€2.85/km` читается как цена за километр. Единственная настоящая проблема в
этой строке была языковой — `/км` вместо `/km` — и она закрыта в P0-1.

Единственное, что в этой паре стоило починить, — **кегль**, а не валюта: см. P1-2 (ставка

Вывод для метода: пункт ревью надо проверять на конвенцию репозитория **до** правки, иначе
«фикс» одного места ломает восемь остальных.

## P2 — разрывы потока и взаимодействия

### P2-1. «Loads towards» — тупик

`Home.tsx:55-66`: блок **`<div>`, не интерактивный**. Он читает `state.route.to`, но менять его
нельзя — направление задаётся только на `/search`, отдельным роутом.

Направление — самая характерная черта этого продукта: это не доска грузов, а «грузы **в сторону**
Брюсселя». Сейчас эта идея подана кеглем 12/14px и ведёт в никуда. Водитель на главном экране
не может сменить пункт назначения.

**Правка:** сделать направление редактируемым героем экрана — крупная тапабельная строка
назначения, открывающая `Sheet` с выбором. Это «самое характерное в мире предмета» в форме
заголовка, и оно же решает P1-2 по иерархии: направление крупно, ставка крупно, остальное мелко.

### P2-2. Таб Map — статичная картинка без маркеров

`SmartLoadList.tsx:89-94`:

```tsx
<img src={mapArt} alt="" className="absolute inset-0 h-full w-full object-cover" />
```

Ни маркеров, ни пинов, ни хало, ни взаимодействия. При этом `ApproachMap.tsx` и `RouteMap.tsx`
**уже замерены с маркерами** (PORT-LOG §4.8: хало 64×64 на (58,333), пин 20×20 на (80,355),

То есть компонент с маркерами существует, а экран его не использует — прямое нарушение
AGENTS.md #4 («composed, never copy-pasted») и расхождение с собственной картой.

**Правка:** композиция `RouteMap` вместо голого `<img>`; маркеры грузов из `visible`,
тап по маркеру скроллит к карточке в нижней ленте (snap уже настроен, строка 95).

### P2-3. Загрузка — строка текста вместо замеренного скелетона

`SmartLoadList.tsx:80`: `<p role="status">Searching for loads…</p>`.

Токен `color-offer-bg-skeleton` существует, вариант `OfferCard` Loading (194px, узел `2594:22017`)

**Правка:** переиспользовать замеренный скелетон. Он даёт стабильность раскладки —
карточки не «прыгают» при появлении данных, что важно на телефоне в руке.

### P2-4. Пустое состояние без действия

`SmartLoadList.tsx:82`: `No loads match these filters.` — констатация, без выхода.

Пустой экран — приглашение действовать, а не констатация тупика.

**Правка:** `No loads match all three filters` + действие `Clear filters`
(сбрасывает `on` в `Home.tsx:35`). Показывает, сколько фильтров активно, и даёт один тап наружу.

### P2-5. Модалка `Sheet` — нет Escape, ловушки фокуса и inert-фона

`Sheet.tsx` целиком: скрим-кнопка + панель. Нет:

- закрытия по `Escape` (ожидание любой модалки);
- переноса фокуса в диалог при открытии;
- возврата фокуса на триггер после закрытия;
- `inert` / `aria-hidden` для содержимого под скримом — скринридер уходит в ленту под модалкой.

`role="dialog" aria-modal="true"` стоит на вложенном `<div>` в `QuickApplyModal`, а не на панели
`Sheet` — то есть диалог объявлен внутри, а сам слой, содержащий скрим, им не является.

### P2-6. Тап-таргеты ниже 44px

Замер `getBoundingClientRect` на `/v2` (iOS HIG минимум 44×44):

| Элемент | Размер | |
|---|---|---|
| `Today` / `€3+/km` / `Under 30 km` | 70×36 / 82×36 / 115×36 | SMALL |
| `List` / `Map` | 180×34 | SMALL |
| **`Lille → Brussels`** (открытие деталей карточки) | **344×20** | SMALL |
| `Demo` | 59×28 | SMALL |
| `Apply for €360` | 344×48 | ok |
| Таб-бар | 110×50 | ok |

Худший случай — **344×20**: основная зона тапа карточки (маршрут) высотой 20px.
Водитель в перчатках, телефон в одной руке. Токен `control.h` = 48px существует и для
главного CTA соблюдён — но не для вторичных зон.

**Правка:** фильтры и табы → минимум 44px высоты; маршрут — расширить зону тапа паддингом
(`py-[12px] -my-[12px]`), не меняя визуальный кегль.

### P2-7. Карточка: вложенная интерактивность и aria-label с внутренним id

`LoadCard.tsx:74-76`:

```tsx
<article aria-label={`Load ${load.id}`} onClick={…} className="cursor-pointer …">
```

Проблемы:

- `aria-label="Load NORD-1"` — скринридер читает **внутренний идентификатор** вместо смысла.
  Водителю нужны ставка и маршрут, не id.
- `<article>` с `onClick` и `cursor-pointer` содержит `<button>` (маршрут) и `LoadCta` —
  вложенная интерактивность, клик фильтруется через `closest('button, a')`. Хрупко и не объявлено.
- У самого `<article>` нет клавиатурного доступа: Enter на карточке не работает,
  только через вложенную кнопку маршрута.

**Правка:** `aria-label` из содержания — `` `${load.from} to ${load.to}, €${load.rate}, ${load.perKm}/km` ``;
карточке — `role="button"` + `tabIndex={0}` + обработчик Enter/Space, либо убрать клик с контейнера
и оставить один явный тап-таргет. Первый вариант сохраняет текущий UX.

## Предлагаемая схема карточки (после правок)

Одно смелое место — ставка. Всё остальное тише. Убрано: плавающий бейдж справа, второй `€`,
глифы, дублирующая палитра.

```
┌──────────────────────────────────────┐  ← без border-l-4 с 2026-10-10 (просьба клиента);
│ (clock) In review         12px pill  │  ← Icon, не глиф; состояние — только пилюля
│                                      │
│ €360              metric-28 / 700    │  ← ЯКОРЬ (был heading-20/600)
│ 2.85/km · 126 km   caption-12        │  ← без второго €
│                                      │
│ Lille ────────────────► Brussels     │  ← heading-20/600, тап ≥44px
│                                      │
│ Today · 08:00–10:00                  │  ← body-14, одна строка
│ 28 km to pickup · 32 min · 126 km    │
│ NordCargo · (star) 4.8 · Paid in 7d  │  ← Icon star
│                                      │
│ ┌──────────────────────────────────┐ │
│ │        Apply for €360            │ │  ← control-h 48, focus-ring
│ └──────────────────────────────────┘ │
└──────────────────────────────────────┘
```

Было 7 разрозненных строк с бейджем в отдельном ряду; стало 5 сгруппированных блоков:
бейдж → ставка → маршрут → факты → действие. Цена и маршрут — два визуальных уровня,
разнесённые кеглем, а не весом одного кегля.
